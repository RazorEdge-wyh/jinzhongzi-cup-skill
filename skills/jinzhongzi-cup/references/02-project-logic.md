## 1. 一页项目卡

| 字段 | 内容 |
|---|---|
| 项目名 | 菌护禾 |
| 一句话 | 在菌最容易死、作物最需要它的那几周（定殖窗口 0–30 天），用一套 150 元级的微灌装置，在土壤偏干且温度适宜时自动小水量补墒，把根际活菌数托在功能阈值以上，窗口结束系统退出。 |

| 现有方案缺口 | ①国外产品（如 Smart-mip）解决"出厂存活 + 下地快速定殖"，下地后无持续维护；②国内产品卷浓度与剂型，施用即结束；③传感器触发灌溉的框架/专利多为"该补菌了"的补施逻辑；④包埋材料作用在入土前与入土瞬间，覆盖不了入土后的环境波动；⑤缺 0–30 天窗口内"触发 vs 常规接菌"的田间活菌数对照证据。 |
| 方案 | 窗口期内只做一件事：水分低于标定阈值且温度适宜 → 自动一次小水量微灌；必要时窗口初期加低浓度蔗糖作趋根信号；窗口结束退出。 |
| 三个不同点 | ①触发依据：判断"菌是否面临早期胁迫、需要短暂托住"，不是"是否需要补菌"；②限时退场：只管理 0–30 天，设最小灌溉间隔与单次水量上限，避免根际缺氧；③糖是信号不是营养：低浓度蔗糖诱导菌发挥功能，若预实验无效则该模块直接删。 |

## 3. 方案与工作流（评委要能听懂"到底装了什么、什么时候动作"）

```
传感器（10 cm 水分 ×2 取中值 + DS18B20 温度）
        │  每 N 分钟采样
        ▼
   ESP32 判定：水分 < 阈值  AND  温度 ∈ 适宜区间  AND  距上次灌溉 ≥ 最小间隔
        │  是
        ▼
   继电器 → 小水泵 → 滴灌/微喷 → 单次水量 ≤ 上限 → 记录
        │  窗口初期前 k 次：同步加低浓度蔗糖（可删模块）
        ▼
   第 30 天：系统退出（或转人工）
```

三条设计约束（写进材料的技术亮点）：
1. **双条件触发**（水分 + 温度）而非单一水分阈值 → 温度不适宜时不触发，减少无效灌溉。
2. **防过灌**：最小灌溉间隔 + 单次水量上限 → 避免连续灌水造成根际缺氧（这是"托菌"变"淹菌"的最大风险，必须主动写出来）。
3. **限时退场**：只管理 0–30 天，控制成本、避免与农户既有管理冲突，也让"效果归因"更干净。

## 4. 指标与口径（全链路唯一，改口径必须同步 BP/PPT/论文）

| 指标 | 定义 | 单位 | 测定时点 | 方法 | 备注 |
|---|---|---|---|---|---|
| 根际活菌数 | 根际鲜土中目标芽孢杆菌可培养数 | CFU/g 鲜土 | 第 0（处理后）、7、15、30 天 | 梯度稀释涂布平板，3 重复，取均值±SD | **硬指标**；需抗性标记或选择性培养基区分土著菌 |

| 土壤含水量 | 体积含水率 | %（VWC） | 连续 | 电容式传感器（已标定） | 需给出标定方法与漂移复核周期 |

| 亩均投入 | 单点成本 × 每点数量/亩 + 运维 | 元/亩·季 | — | 由 BOM 与布点方案推导 | 布点密度需实测/文献支持 |
| 亩均收益 | 增产收益 + 减药减苗收益 − 投入 | 元/亩·季 | — | 田间对照产量 × 单价 | 单价用当地收购价并注明时点 |

判定规则（预注册，写进试验方案，避免"事后找显著"）：
- 主假设：触发组第 7/15 天根际活菌数 > 常规接菌组（单尾，α=0.05）。
- 样本：每处理 ≥3 个独立小区/重复；每小区 ≥5 点混合取样。
- 若第 7/15 天无显著差异 → 触发条件或阈值需重标定；连续两轮无效 → 项目转向（写进 BP 的"止损条件"，反而是加分项）。

**单位经济模型（公式，答辩现场可复算）**：

```
每亩投入 = 单点成本 × 每点数量/亩 + 运维成本/亩
每亩收益 = Δ产量 × 收购单价 + 减施化肥节省 + 减死苗补苗节省 − 每亩投入
投资回收期 = 每亩投入 / 每亩年净收益
```

关键待实测参数：**每点覆盖面积**（决定每点数量/亩）、Δ产量、Δ死苗率、每亩运维（电池/传感器更换、复核人工）。**在拿到这些数之前，任何"亩均增收 X 元"都必须写成假设并标注区间**。

## 6. 评委最可能攻击的 8 点（每点配一句可用的回应骨架）

1. **"为什么不直接补施一次菌剂？"**
   → 菌剂成本低但人工高，且补施时点难判断；本项目比的是"触发组 vs 常规接菌 vs 窗口后补施"三组，补施组的成本与效果会作为对照写进材料。**这条必须有数据，否则是最大软肋。**
2. **"活菌数上去了，产量一定上去吗？"**
   → 不承诺。第一阶段以活菌数为硬指标（可测、周期短），产量作为第二阶段指标；评审逻辑是"先证明能托住，再证明托住有用"。
3. **"传感器漂移怎么办？"**
   → 4–6 周复核一次，双传感器取中值，标定曲线随设备交付；更换成本计入运维。
4. **"150 元怎么算的？"**
   → BOM 表 + 3 家询价 + 场景差异（市电/光伏）；承认这是物料成本，不含安装人工。
5. **"和 Smart-mip / 包埋材料比优势在哪？"**
   → 不正面比"谁更好"，比"管的时段不同"：它们管出厂与入土瞬间，本项目管入土后 0–30 天，可叠加使用。
6. **"你怎么证明效果是你的装置带来的，不是农户自己浇水？"**
   → 三组对照 + 记录每次触发日志 + 对照组同步记录灌溉；这也是 AI/评委最认的"可核查"设计。
7. **"草莓能推广到水稻茶叶吗？"**
   → 不外推。12 个月内只做草莓主效应，其他作物列为后续验证。
8. **"团队/公司/财务在哪？"**
   → 当前阶段如实说明，给出补齐时间表（见 §7）。

## 8. 可外推边界（写进论文与 BP 的"局限"节，主动写反而加分）

- 作物：草莓（设施）为主；水稻、茶叶等仅作机制旁证，不外推。
- 区域：湖南及相似气候区设施栽培；露地/高盐/重茬极端田块需另行验证。
- 菌株：方案稿围绕枯草芽孢杆菌；换菌株需重做定殖与触发阈值。
- 时间：仅覆盖 0–30 天窗口；窗口后管理不在本项目范围。
- 机制：糖信号为假设，预实验无效即删模块（保留"可删设计"本身是诚实性证据）。

## 2. 逐条修法

| 提示 | 怎么修 |
|---|---|
| 缺少章节（7 条） | 按 `assets/templates/project-plan-skeleton.md` 补章节：证据链、方案、差异点、市场/产业、团队、社会价值、落地；每节先写一句"回应哪条评分" |
| 空话/无证据最高级 | 删除或改成可证明表述：`国际领先` → `在本研究条件下，第 7 天活菌数比对照高 X 倍` |
| 数字无来源 | 补来源（文献/实验/官方统计），或改为 `[估算]` 并写清假设，或改为"待验证" |
| 正文批注残留 | 提交版删掉 `[实测]/[估算]/[待补]/[核实 Sx]`、emoji、`> 自检清单`；数据诚实性改由"文首数据声明 + 财务假设"承担 |
| 标签体句式 | `定位宣言：` → 改成叙述句；同类：`核心逻辑：`、`一句话概括：`、`系统架构一句话：` |
| 未发现 [实测] 标记 | 先把能测的数字测出来；测不了的写 `[估算]` 并给假设，或 `[待补]` 并给验证计划 |
| 评审维度对照表缺失 | 复制 `assets/templates/judging-mapping.md`，把"评分要点 ↔ 章节 ↔ 证据"填满 |
| 五维覆盖偏弱 | 该维度缺内容：团队维度缺分工/股权/顾问；社会价值缺量化指标；市场维度缺客户/规模 |
| 图表编号不连续（如有） | 按出现顺序重编（图 1、图 2…），并检查正文是否引用了不存在的编号 |

## 3. 建议的修复顺序

1. **先修错误**（缺章节、引用断裂）——这些会导致"未通过"。
2. **再补 `[实测]`**——把能测的数字测出来，替换掉 `[估算]` 与 `[待补]`。
3. **最后清批注与空话**——定稿前的最后一步。

## 4. 在 CI 里使用

```bash
# 有错误即失败（适合材料仓库的 CI）
python skills/jinzhongzi-cup/scripts/check_submission.py 材料.md --kind plan

# 警告也当失败（更严格）
python skills/jinzhongzi-cup/scripts/check_submission.py 材料.md --kind plan --strict

# 输出 JSON，交给其它脚本汇总
python skills/jinzhongzi-cup/scripts/check_submission.py 材料.md --kind plan --json
```

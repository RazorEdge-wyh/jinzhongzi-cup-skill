# 设计说明（Design）

## 1. 要解决的问题

大学生创新创业赛事（金种子杯、创新大赛、挑战杯）的材料写作有三个稳定痛点：

1. **规则易错**：分值与权重逐届变化（市场 30→20、财务 15→20、社会价值 10→15），网上大量过时攻略仍在流传。
2. **数据易假**：agent 生成材料时最容易"顺手编一个看起来合理的数"，而这类比赛对真实性是一票否决。
3. **格式易散**：BP、路演、论文三套材料各写各的，口径互相打架；论文格式（GB/T 7714）细节多，人工核对成本高。

本 skill 把这三件事变成**可执行的约束 + 可机械检查的规则**。

## 2. 设计原则

| 原则 | 落地方式 |
|---|---|
| **证据优先** | 所有断言先进 `evidence-ledger`；数字三分类 `[实测]/[估算]/[待补]`；linter 检查无来源数字 |
| **口径唯一** | `references/02` 锁定活菌数、窗口期、判定时点、单点成本；改口径必须全链路同步 |
| **按需加载** | `SKILL.md` 只放路由与铁律；细节在 `references/`，用到才读（progressive disclosure） |
| **可机械校验** | `scripts/check_submission.py`：结构、空话、批注残留、标签体、引用、五维覆盖 |
| **可审计** | 规则带来源与核实日期；`08/09` 逐条 `[核实 Sx]`；冲突时以官方通知为准 |
| **可移植** | 遵循 Agent Skills 规范，DSH / Claude Code / ZCode 均可安装 |

## 3. 组件关系

```
SKILL.md（路由 + 铁律 + 质量门）
   ├── references/01  赛制基线（权重演变、12 分钟、材料清单）
   ├── references/02  项目事实底盘（证据链、口径、缺口）
   ├── references/03  BP / 路演 / 答辩
   ├── references/04  论文速查（IMRaD、引用、图表、AI 声明）
   ├── references/05  试验设计与统计
   ├── references/06  AI 网评适配
   ├── references/07  来源总账（A>B>C>D 权威性分级）
   ├── references/08  论文规范核实版（20 来源）
   ├── references/09  赛事方法论核实版（21 来源）
   ├── assets/templates/  6 个填空模板（含证据台账、评审维度对照表）
   └── scripts/check_submission.py  提交前 linter
```

## 4. 关键机制

### 4.1 证据台账（evidence ledger）
每条断言一行：ID / 断言 / 类型 / 来源 / 时点 / 口径 / 状态 / 用在哪 / 风险。材料里的每个数字都必须能追到一行；"待实测"的行不得写成既成事实。

### 4.2 数字三分类
- `[实测]`：有实验/检测/合同/官方统计支撑
- `[估算]`：有推导但无直接数据（必须写假设）
- `[待补]`：没有，必须补（写目标值 + 验证方法）

三类的比例本身就是材料可信度的信号；linter 会统计并提示。

### 4.3 评审维度对照表
把"评分要点 ↔ 章节 ↔ 证据"三列填满。填不满的行就是缺失的证据；也便于评委/AI 快速定位。

### 4.4 去 AI 感写作纪律
叙述体优先、禁标签体、正文零批注、套话克制、图表规范、学生陈述语气。linter 检测"定位宣言：""核心逻辑："等标签体与批注残留。

## 5. 已知限制

1. **规则会过期**：`01` 的核实日期是 2026-10-22；拿到正式通知后必须更新"仍待核实"清单。
2. **linter 只做机械检查**：不能判断论证是否成立、数据是否真实；它只能发现"看起来像问题"的地方。
3. **项目事实绑定**：`02` 是菌护禾项目卡；换项目需替换该文件（其余文件通用）。
4. **指标口径**：活菌数等指标定义适用于本项目；其它项目需改写 §4 口径表。
5. **不替代真实实验**：论文/试验方案中的 `【待填】` 必须由真实实验填充。

## 6. 扩展点

| 想扩展 | 改哪里 |
|---|---|
| 换一个赛事 | 复制 `01`，按 `09` 的对照表改权重；`SKILL.md` §1 路由指向新文件 |
| 换一个项目 | 替换 `02`；同步 `01` 的赛道归属 |
| 增加材料类型 | `check_submission.py` 的 `REQUIRED_SECTIONS` 加一种 kind |
| 增加检查规则 | 在 `check_submission.py` 加 `check_*` 函数并在 `main()` 汇总；在 `tests/` 加 fixture |
| 增加导出格式 | `tools/md2docx.py` 已支持 Word；LaTeX 用户可套 ustcthesis 模板 |

## 7. 安全与诚信边界

- 不生成/不美化实验数据、订单、专利、获奖。
- 不预测获奖、不承诺投资。
- 引用 AI 生成的文献必须逐条核对原文（`04` §6 有依据）。
- 参赛材料的真实性由用户负责；本 skill 提供的是"不造假的结构与检查"。
